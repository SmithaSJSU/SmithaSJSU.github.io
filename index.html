CMPE 252 · fall 2026 · team of 2in progress

Does near-lossless quantization hold up when the scene changes?

Quantizing the vision encoder of π0, a 3.3B-parameter vision-language-action robot policy, to 4 bits costs only 1.5 points of task success on clean LIBERO benchmarks. We test whether that gap grows when lighting, backgrounds, and object layouts change, using matched closed-loop simulation episodes and a difference-in-differences metric we call the Quantization Robustness Penalty (QRP).

  • I own the LIBERO-Plus integration: a benchmark runner that samples perturbed task variants by shift type and difficulty, rebuilds the clean tasks the suite leaves out, maps each variant back to its base initial states, and gives the policy the original instruction to avoid a known prompt leak.
  • I run the visual-shift experiments (lighting, background, layout; about 3,000 episodes) and compute the primary result: pooled QRP with a paired, task-clustered bootstrap interval, judged by a decision rule fixed before any core run.
  • Set up the team's GPU infrastructure on Google Cloud and the repo workflow: one pinned environment for every core run, cross-review before merge, and a design freeze after the pilot.

CMPE 258 · fall 2026 · team of 3in progress

What breaks modern audio deepfake detectors?

A controlled study on ASVspoof 5 and DFADD: which shift hurts most — unseen generators, codecs, or adversarial post-processing — and do SSL detectors fail differently from AASIST?

  • I own the evaluation harness: protocol parsing, shift slices with utterance-level codec and adversarial pairing, speaker-level bootstrap intervals, and every results table and figure in the report.
  • It already reproduces the official ASVspoof 5 AASIST metrics — 15.20% dev EER against the 15.2% published — which is what licenses every comparison built on top of it.
  • I run the falsification controls (random scores, 8 kHz downsampling, VAD-trimmed reruns) that stop a “codec effect” from turning out to be a pipeline artifact, and the DFADD cross-dataset evaluation against recent diffusion and flow-matching TTS.
  • Demo application, plus INT8 quantization and CPU latency per shift if the core results table lands on schedule.

CMPE 257 · fall 2026 · team of 3in progress

Uncertainty for TinyML in a single forward pass

Re-implementing QUTE (ICML 2025) from the paper alone, with no reference code: two lightweight output heads on one CNN, trained by copying early-exit weights into them before every batch, so confidence falls when accuracy does without a second forward pass.

  • I own the model and the shared interface: the base CNN and prediction contract the rest of the team builds against, then the early-exit branches, output blocks, weight-transfer training loop, and the ablation that removes it.
  • Comparing against softmax confidence, MC Dropout, and deep ensembles on calibration, label-free accuracy-drop detection across 15 corruptions, and parameter cost.

// 03 · about

Hardware discipline, ML curiosity.

My first job was writing C for diesel engine control units, where code has to meet timing deadlines and every fault has to be caught and logged. That taught me to treat software as something that must work on real hardware, every time.

Today I bring that mindset to machine learning: evaluating models under distribution shift, estimating uncertainty cheaply enough for tiny devices, testing whether quantized robot policies hold up under visual shift, and treating LLM output as untrusted input.

Between those chapters I founded and ran an arts education studio and led operations for a nonprofit across five sites and 90+ staff, so I also know how to plan, communicate, and get a team across the finish line.
